# Optional team policy service

`tirith-policy-server` is an explicitly operated policy authority for a team that brings its own hosting. Personal Tirith protection needs no server. Installing or starting Tirith does not install, enroll in, or start this executable. This service has no license or payment integration.

This first native storage implementation supports ordinary Linux/macOS accounts. It refuses root and differing real/effective UIDs. Windows service storage is unavailable pending an equivalent native ACL implementation; this does not restrict the cross-platform protocol/client. Use a local filesystem with ordinary SQLite durability guarantees. Network filesystem and power-loss durability are not qualified by unit tests.

## Initialize and operate

Build the separate workspace package with `cargo build --release -p tirith-policy-server`. All service commands use an explicit absolute `--data-dir` before the subcommand. Paths must traverse real, trusted directories; a symlink spelling such as macOS `/tmp` must instead use its actual `/private/tmp` path. The init command creates only the final data directory, privately, and refuses an existing path. Input YAML must be a bounded, ordinary-owner regular file. Existing secret/output parents must already be private.

```text
tirith-policy-server --data-dir /absolute/private/authority init --policy /absolute/policy.yaml
tirith-policy-server --data-dir /absolute/private/authority identity
tirith-policy-server --data-dir /absolute/private/authority serve --listen 127.0.0.1:8778
```

Initialization prints the random authority UUID, policy UUID, current revision and roster revision. Keep these IDs when reviewing a connection. `identity` reads them again. Initialization imports actual validated policy; no empty remote policy or local fallback authority is silently substituted.

`issue-credential` requires `--authority`, `--role publisher|observer|client`, `--principal`, `--expires-unix-ms`, and a new `--output` file. A client role also requires `--client`; other roles refuse it. Choose a stable nonzero canonical UUID for a principal and preserve it during credential rotation. Expiry is explicit, later than now and at most90 days away. The command writes32 random bytes as64 lowercase hexadecimal characters plus one LF to a new0600 file, and prints only the credential ID and file path. It never overwrites or prints the secret. A failed write/commit can leave that private file, with credential activation unknown; inspect the bounded local `credentials --authority UUID` inventory and revoke an uncertain credential before using it, or issue a new explicitly selected file. Do not assume an error deleted the file or guaranteed no database commit.

`credentials --authority UUID` prints the bounded local credential inventory with IDs, principal/role/client, expiry and revocation state; it never prints token text or hashes. This also lets an operator find and revoke a credential whose creation reply was lost. `revoke-credential --authority UUID --credential UUID` revokes an existing credential. Rotation means explicitly issuing a replacement with the same intended principal, role and client, then revoking the old credential. No credential carries implicit publication rights.

`register-client --authority UUID --expected-roster UUID` registers one target and returns its new client UUID plus updated roster revision. `deactivate-client` additionally takes `--client UUID` and requires the current roster revision. Deactivation retains its sequence/history record and immediately prevents its credentials from authenticating. There is no automatic enrollment, roster discovery or reactivation that resets a report sequence.

An operator may explicitly import another file with `import --authority UUID --expected-revision UUID --policy /absolute/policy.yaml`. This retains prior YAML and creates a new random revision only if the current revision still matches. A local import is owner administration; it is not recorded as a reviewed HTTP publication. It makes older publication rollback ineligible. Remote publishers must use the reviewed publication protocol.

## Hosting boundary

The listener accepts loopback addresses only. Put an operator-managed HTTPS reverse proxy in front of it for remote access and restrict access to the intended team. Preserve exactly one Authorization header, enforce comparable body/header/time limits, disable request/response body logging, and do not log bearer credentials. The service does not trust forwarding headers and rejects every Origin header. It has no cookies, CORS, browser login, public enrollment or URL credentials.

Tirith client connections use public-HTTPS endpoint admission and guarded DNS by default, with no ambient proxy or redirects. A deliberately private LAN/tailnet endpoint requires one to eight distinct per-connection pins, selected with repeated `tirith policy team connect --address IP_ADDRESS` options. For example, `--server-url https://policy.example.test:8443 --address 10.20.30.40` connects only to that address while still verifying the HTTPS hostname and certificate. Add `--private-ca-file /absolute/private/team-ca.pem` when the endpoint uses your private CA. There is no TLS-disable option. Metadata hosts and prohibited addresses, including cloud metadata and link-local endpoints, remain refused even with explicit pins. The loopback HTTP listener does not disable the product client's TLS requirement. A successful local test does not qualify a remote proxy deployment.

## API and replay

The shared `tirith_core::policy_team` types define schema1 and contract `tirith_policy_management_v1`. All request objects reject unknown fields. IDs must be canonical lowercase nonzero UUIDs. Every route except `/healthz` requires exactly `Authorization: Bearer ` followed by64 lowercase hex characters. Query strings, URL authority forms and noncanonical route IDs refuse. JSON requests use `Content-Type: application/json`. All responses are bounded, `Cache-Control: no-store`, and contain fixed error codes without private diagnostics.

| Route | Role and result |
| --- | --- |
| GET `/api/policy/v1/capabilities` | Any role; authority/policy/role/expiry/limits. Client role additionally receives its stable client ID and current report-sequence high-water. |
| GET `/api/policy/v1/current` | Any role; current exact YAML and random revision. |
| GET `/api/policy/fetch` | Any role; legacy YAML, with `X-Tirith-Authority-Id`, `X-Tirith-Policy-Id`, `X-Tirith-Policy-Revision`. Fetching never emits an applied report. |
| POST `/api/policy/v1/publications` | Publisher; exact reviewed candidate, authority/policy/current-revision CAS, operation ID and review commitment. Review age must be below24 hours. |
| GET `/api/policy/v1/operations/{id}` | Publisher/observer; closed operation status without YAML, token hashes or private commitments. |
| POST `/api/policy/v1/reconcile` | Publisher; read-only lookup of the exact retained publication/rollback request and principal. Never publishes or creates a missing operation. |
| POST `/api/policy/v1/rollbacks` | Publisher; original publication, current-revision CAS and fresh operation ID. Restores exact retained prior YAML as a new revision before7 days, only while that publication is still current. |
| POST `/api/policy/v1/reports` | Client; its own monotonic sequence and bounded closed observation. |
| POST `/api/policy/v1/reports/reconcile` | Client; read-only exact principal/client/full-request lookup of its latest retained report. Never inserts, advances sequence, or submits an Applied observation. |
| GET `/api/policy/v1/status` | Publisher/observer; every explicitly active registered client, current revision, sample time and latest authenticated self-report. |

Publication and rollback reauthenticate and bind scope inside an immediate SQLite transaction. A same-principal identical operation retries to its retained result before checking current revision/review age again. Changed intent or a different principal reusing the ID refuses. Authenticated structurally valid age/CAS/rollback refusals are retained as immutable rejected operations. Unauthenticated or malformed input creates no operation. Private commitments record submitted intent and review claims; the server does not independently prove that a client reviewed a candidate.

A timeout, dropped connection, busy/full database or failed commit can leave a mutation outcome unknown. Reconcile the exact operation ID or retry the exact intent; do not invent a fresh ID and assume the previous attempt had no effect. A retained operation response includes the current revision at the time of the query, while its published revision and committed/rejected outcome remain historical.

Reports have `report_sequence` in1..=9223372036854775807. Derive `report_id` with the shared helper: SHA256 over ASCII `tirith-policy-client-report-id-v1` plus NUL, canonical authority UUID bytes, canonical client UUID bytes, and the sequence as eight big-endian bytes; take16 bytes and set UUID version8 and RFC variant bits. This hashes public identifiers only. The server retains one latest row per client: exactly high-water+1 advances; an identical latest sequence/principal/intent returns its original receipt; older or skipped sequences refuse. Changed latest intent refuses. Credential rotation cannot reset high-water. A later report replaces the earlier observation; the server does not promise an unbounded reporting history or replay of superseded reports.

`reports/reconcile` authenticates the same Client principal and compares the complete original request, including report ID, sequence, revision, observation time and state. It can return the original receipt for an old observation without requiring that observation to satisfy freshness for a new mutation. The endpoint is read-only; missing/superseded exact intent returns `OperationNotFound`, which does **not** prove no prior commit. Changed intent or a different principal cannot recover another request's receipt. The client command is `tirith policy team enrollment reconcile --report-id REPORT_UUID`; `--archive-id ARCHIVE_UUID` selects an exact local historical context.

Client recovery is independent of server operation history. `enrollment disable --expected-activation-id ACTIVATION_UUID` withdraws a parsed activation offline. For unreadable activation fields, `enrollment repair --remove-malformed` explicitly removes only the currently malformed bounded private enrollment via one retained native witness; valid or changed records refuse. Neither action revokes credentials, deletes a report, or claims fleet withdrawal.

The client privately saves every exact pending report before sending. Explicit `enrollment abandon --report-id REPORT_UUID --acknowledge-unknown-outcome` preserves that request/context as locally archived unknown, not cancelled or proven uncommitted. Its fixed 16 KiB report file holds at most four historical entries and refuses either bound without silent eviction. New reporting requires fresh valid Runtime and authenticated sequence; an older late commit can still cause an explicit conflict. Read-only reconciliation of a retained archived context never relaxes the requirements for a new Applied report.

Observations must reference a known retained revision, occur no more than60 seconds ahead, be less than24 hours old, and advance the prior observation time. Missing reports mean unreported, never proof of offline state. Downloaded, failed and applied are closed client assertions. `applied_current` means only that an authenticated client reported applying the sampled current revision. `fleet_adoption_verified` is always false. Complete roster coverage means only that all explicitly registered active targets are included, and creates no current enforcement authority.

## Storage bounds and recovery

The database uses FULL synchronous transactions, foreign keys, a4096-byte page size and a192MiB main-file page cap. DELETE journaling avoids an unbounded WAL; a rollback journal can temporarily require additional filesystem space. There are at most2048 retained credentials,1024 registered clients including deactivated entries,128 policy revisions,4096 publication/rollback identities, and one latest report per registered client. Caps refuse visibly; identities are not silently discarded to permit replay. Plan explicit authority migration before infrequent publication/credential caps are reached.

The service retains native directory and main-file identities and refuses links, foreign ownership, shared private modes, unsafe ACLs and unsafe existing sidecars. Database and sidecar revalidation use metadata calls, without opening and closing the target: a foreign descriptor close would release SQLite's POSIX process locks. Within one process, stores for the same inode share one retained connection and witness. A registry serializes first admission and final teardown, closing SQLite before its witness. macOS checks the retained database ACL by descriptor and sidecar ACLs through nofollow metadata inspection. Library callers must also avoid unrelated raw opens/closes of a live database inode, as required by SQLite. This is ordinary operator-owned storage, not protection against the operator or arbitrary same-UID code. A rejected operation does not authorize deleting files or replacing a live database. Preserve failed initialization data for explicit inspection; init never retries over an existing directory.

Use a private, consistent SQLite backup while service and all local administration are stopped, or an independently operated SQLite backup procedure. Preserve the complete database and authority IDs. Restoring an older backup also restores older revocations and sequence high-waters; do not serve a stale backup as though it represented current authority. Reconcile credentials/publications with the team before returning it to service. Do not copy a live database alone while journal activity is in progress.

At most32 connections and32 database workers are admitted. Each connection has one10-second deadline covering headers/body/response, no keepalive, and32 headers/32KiB HTTP buffer bounds. Requests and policy YAML are capped at2MiB and1MiB, reports at8KiB. Database work receives the original deadline; queued mutex acquisition and the last pre-commit check do not renew it. A worker retains its permit if its HTTP response disappears. Native filesystem calls and SQLite COMMIT cannot be safely canceled halfway through; transport loss still means unknown. These bounds do not claim reliable completion on a stalled network filesystem.

The native Rust tests exercise ordinary-owner storage, real SQLite transactions/full-cap failure, concurrency/replay, rollback, monotonic reports, private credentials and actual loopback slow requests. Separate-process regressions require a second SQLite writer to remain blocked after identity checks, same-process reopen/handle release, and sidecar hardlink refusal; a macOS-specific row checks unsafe database ACL refusal. They do not qualify a deployed HTTPS proxy, independent client enforcement, power loss or a production fleet.
